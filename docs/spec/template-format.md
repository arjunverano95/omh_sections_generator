# Template Format

Part of the [Sections Engine Specification](README.md). This document defines every file a template is made of, how fields and layout are written, and the rules the compiler enforces. [compiler.md](compiler.md) says what these files become; [renderer.md](renderer.md) says how the result is drawn.

## 1. Files

```
templates/<name>/
  template.yaml          manifest (required)
  theme.yaml             tokens and variants (required)
  globals/header.yaml    (required)
  globals/footer.yaml    (required)
  sections/*.yaml        one section per file (at least one)
  seed/pages.yaml        demo content, read by the seeder (optional)
  seed/globals.yaml
  seed/forms.yaml
  seed/media/*           files the seeds reference
  assets/*.png           block preview images shown in the admin (optional)
```

All files are YAML 1.2. JSON is valid YAML, so a `.json` file with the same shape loads too. Nothing in a template folder is executable.

Each file may start with a schema comment so editors validate and complete it:

```yaml
# yaml-language-server: $schema=../../schema.json
```

`templates/schema.json` is generated by the compiler from the same definitions it validates with (see [compiler.md section 8](compiler.md#8-json-schema)).

## 2. Manifest: `template.yaml`

```yaml
name: template-1            # folder name; [a-z0-9-]
label: Studio               # shown in the admin (block group, seed button)
description: Light, editorial, serif headings.
theme: ./theme.yaml
globals:
  header: ./globals/header.yaml
  footer: ./globals/footer.yaml
sections: ./sections        # folder; every *.yaml inside is a section
```

| Key | Required | Rule |
| --- | --- | --- |
| `name` | yes | Equals the folder name. Lowercase letters, digits and hyphens. Becomes the block-slug prefix. |
| `label` | yes | Human name of the face. |
| `description` | no | Free text. |
| `theme` | yes | Path, relative to the manifest. |
| `globals.header`, `globals.footer` | yes | Paths. Both are required: a face without a header or footer is not a face. |
| `sections` | yes | Folder path. Files are loaded in name order; the admin lists blocks in that order. |

## 3. Theme: `theme.yaml`

```yaml
fonts:
  sans: Inter                       # Google Fonts family name
  heading: Playfair Display         # defaults to sans
  # mono is not themeable; the stock Geist Mono stays

colors:
  light:                            # required
    background: oklch(99% 0.005 90deg)
    foreground: oklch(18% 0.01 60deg)
    primary: oklch(42% 0.12 255deg)
    primary-foreground: oklch(98% 0 0deg)
    muted: oklch(95% 0.01 90deg)
    muted-foreground: oklch(45% 0.01 60deg)
    border: oklch(90% 0.01 90deg)
  dark:                             # optional; stock dark values fill the gaps
    background: oklch(16% 0.01 60deg)
    foreground: oklch(96% 0.005 90deg)

radius: 0.5rem

variants:                           # named class presets
  heading:
    display: font-heading text-5xl md:text-6xl leading-[1.05] tracking-tight
    section: font-heading text-3xl md:text-4xl tracking-tight
  button:
    primary: inline-flex items-center rounded-md bg-primary px-5 py-3 text-primary-foreground hover:opacity-90
    ghost: inline-flex items-center rounded-md border border-border px-5 py-3 hover:bg-muted
    link: text-sm text-foreground/80 hover:text-foreground
  text:
    lead: text-lg text-muted-foreground
```

**Fonts.** A value is a Google Fonts family name as shown on fonts.google.com, or a map `{ family, weights: [400, 700], subsets: [latin] }`. `sans` is required; `heading` defaults to `sans`. The compiler turns these into `next/font/google` loaders ([compiler.md section 4](compiler.md#4-generated-files)), which is why the names must be literal: `next/font` is resolved at build time and cannot take a variable.

**Colours.** Token names are the slots the stock stylesheet already defines: `background`, `foreground`, `card`, `card-foreground`, `popover`, `popover-foreground`, `primary`, `primary-foreground`, `secondary`, `secondary-foreground`, `muted`, `muted-foreground`, `accent`, `accent-foreground`, `destructive`, `destructive-foreground`, `border`, `input`, `ring`, `success`, `warning`, `error`. `light` must set at least `background`, `foreground`, `primary` and `primary-foreground`; every other slot falls back to the stock value. `dark` is optional and falls back slot by slot to the stock dark set. Any CSS colour syntax is accepted; `oklch()` is what the stock stylesheet uses.

**Radius.** A CSS length. It feeds the `rounded-*` scale through the existing `--radius` variable.

**Variants.** `variants.<group>.<name>` is a string of classes. A layout node references one as `variant: group.name`. Groups and names are free; the compiler only checks that a reference exists. Variants are resolved at compile time into the plan, so the renderer never reads the theme.

## 4. Section file

```yaml
name: hero-split                 # kebab-case; unique within the template
label: Split hero                # block name in the admin
plural: Split heroes             # optional; default is label + "s"
description: Heading and copy on the left, image on the right.
group: Heroes                    # optional; groups blocks in the add-block drawer
preview: ../assets/hero-split.png   # optional

fields:
  eyebrow: text
  heading:
    type: text
    required: true
  description: textarea
  primaryButton: link
  secondaryButton: link
  image:
    type: image
    required: true

layout:
  - div: container grid gap-10 py-20 md:grid-cols-2 md:items-center
    as: section
    children:
      - div: flex flex-col gap-5
        children:
          - text: eyebrow
            as: span
            class: text-sm uppercase tracking-widest text-muted-foreground
          - text: heading
            as: h1
            variant: heading.display
          - text: description
            variant: text.lead
          - div: flex flex-wrap gap-3 pt-2
            children:
              - button: primaryButton
                variant: button.primary
              - button: secondaryButton
                variant: button.ghost
      - image: image
        class: aspect-[4/3] w-full rounded-lg object-cover
        priority: true
```

| Key | Required | Rule |
| --- | --- | --- |
| `name` | yes | `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`. The block slug is `<template>-<name>`; the TypeScript interface is `<Template><Name>Block` in PascalCase. |
| `label` | yes | Shown to editors. |
| `plural` | no | Shown in block counts. |
| `description` | no | Shown in the block drawer. |
| `group` | no | Block drawer group. Defaults to the template label. |
| `preview` | no | Path to a PNG or JPG relative to the file. |
| `fields` | yes | At least one field. Section 5. |
| `layout` | yes | At least one node. Section 6. |

## 5. Fields

A field is `name: type` in the short form, or `name: { type, ...options }` in the long form.

### 5.1 Naming

Names are camelCase identifiers: `^[a-z][a-zA-Z0-9]*$`. They become Payload field names, TypeScript property names and GraphQL names, all of which reject or mangle hyphens. `bullet-icon` is rejected with the fix in the message (`use "bulletIcon"`). Reserved names: `id`, `blockType`, `blockName`, `createdAt`, `updatedAt`. Names are unique within their level (section, or array row).

### 5.2 Types

| Type | Editor sees | Options | Payload field |
| --- | --- | --- | --- |
| `text` | single line | `maxLength` | `text` |
| `textarea` | multi-line plain text | `maxLength` | `textarea` |
| `richText` | the Lexical editor | | `richText` with the project's `defaultLexical` |
| `image` | media picker | | `upload` to `media` |
| `icon` | dropdown of icon names | | `select` over the engine's curated icon list |
| `link` | label, internal page or URL, open in new tab | | the project's `link()` group with appearances off |
| `select` | dropdown | `options` (required): list of values or `{ value, label }` | `select` |
| `number` | number | `min`, `max` | `number` |
| `checkbox` | checkbox | | `checkbox` |
| `array` | repeatable rows | `fields` (required), `min`, `max`, `rowLabel` (a field name in the row) | `array` |
| `form` | picker over Forms | | `relationship` to `forms` |
| `relation` | picker | `to` (required): `pages`, `posts` or `categories`; `many` | `relationship` |

Options every type takes: `label` (defaults to the name, title-cased), `required` (default `false`), `default`, `help` (admin description).

### 5.3 Arrays

```yaml
bullets:
  type: array
  min: 1
  max: 6
  rowLabel: text          # the admin shows this field's value as the row title
  fields:
    icon: icon
    text:
      type: text
      required: true
```

Rows may nest arrays one level deep. Deeper nesting is rejected; it makes the admin unusable and no demo section needs it.

## 6. Layout

`layout` is a list of nodes. A node is a map with exactly one **primitive key** and zero or more options. The primitive key's value is the node's main input.

### 6.1 Primitives

| Key | Value | Renders | Options |
| --- | --- | --- | --- |
| `text` | reference to `text`, `textarea`, `select` or `number` | the value inside `as` (default `p`) | `as`, `class`, `variant`, `if` |
| `richText` | reference to `richText` | the rich text | `class`, `variant`, `if` |
| `image` | reference to `image` | the media, through the project's `Media` component | `class`, `priority`, `sizes`, `if` |
| `icon` | reference to `icon` | an SVG icon | `class`, `size`, `if` |
| `button` | reference to `link`, or a literal (6.3) | an anchor; with `children`, the anchor wraps them | `class`, `variant`, `children` (optional), `if` |
| `div` | class string | an element with children | `as`, `variant`, `children` (required), `if` |
| `each` | reference to `array` | `children` once per row | `as`, `class`, `variant`, `children` (required), `if` |
| `list` | a query (6.4) | `children` once per document | `as`, `class`, `variant`, `children` (required) |
| `form` | reference to `form` | the form, submitting to the form-builder plugin | `class`, `if` |

**`as`.** For `text`: `p`, `span`, `h1` to `h6`, `blockquote`, `small`, `strong`, `em`, `li`, `dt`, `dd`, `figcaption`. For `div`, `each` and `list`: `div`, `section`, `header`, `footer`, `nav`, `main`, `article`, `aside`, `ul`, `ol`, `li`, `figure`. `each` and `list` without `as` render their rows with no wrapper element.

**`class`.** Tailwind classes, applied after the variant's classes. On `div` the primitive key's value *is* the class string, so `div` has no separate `class` option.

**`variant`.** `group.name` from the theme. Allowed on every node; the variant's classes come first, the node's own classes after, so a node can extend or override a preset.

**`if`.** Section 6.5.

### 6.2 References

A reference is a bare field name. It resolves against the nearest scope first: inside `each`, the row; inside `list`, the document; otherwise the section. A name not found in the nearest scope is looked up in the enclosing scopes outward, so a heading declared on the section can be used inside a row.

Dot paths reach into populated relations and documents: `image.alt`, `meta.image`, `author.name`. Paths are checked against what the compiler knows about the target: a `link` exposes `label`, `url`, `newTab`; an `image` exposes the Media document; a `list` row exposes the collection's fields (6.4).

### 6.3 Literals

Text that is not editable is written as `{ value: ... }`:

```yaml
- text: { value: Read more }
  as: span
```

A button whose label is fixed and whose target comes from the data is written with the literal form:

```yaml
- button: { label: Read more, href: url }            # href is a reference
- button: { label: See pricing, href: { value: /pricing }, newTab: false }
```

In the literal button form `label` is text, `href` is a reference unless written as `{ value }`, and `newTab` is a boolean.

A button may carry `children`, in which case the anchor wraps them instead of a label. That is how a logo links home and how a wordmark field becomes a link. With `children`, `label` is optional in the literal form; for a `link` reference, the link's label becomes the anchor's accessible name.

```yaml
- button: { href: { value: / } }
  class: block
  children:
    - image: logo
      class: h-8 w-auto
- button: link                       # a footer social row: icon inside the anchor
  children:
    - icon: icon
```

### 6.4 `list`

```yaml
- list:
    collection: posts            # posts | pages | categories
    limit: 3                     # 1 to 50
    sort: -publishedAt           # one field, leading "-" for descending
    where:                       # optional, Payload where syntax
      categories:
        in: { field: category }  # placeholder: the value of the section's "category" field
  as: ul
  class: grid gap-6 md:grid-cols-3
  children:
    - div: flex flex-col gap-3
      as: li
      children:
        - image: meta.image
          class: aspect-video rounded-md object-cover
        - text: title
          as: h3
        - button: { label: Read, href: url }
```

A row exposes the document's fields plus a synthetic `url` (`/posts/<slug>` for posts, `/<slug>` for pages, `/posts?category=<slug>` for categories). The compiler derives the query's `select` from the references used in `children`, so the query fetches only those fields. Placeholders `{ field: <name> }` inside `where` are filled from the section's data at render time.

### 6.5 Conditions

```yaml
if: backgroundImage                          # truthy: non-empty string, non-empty array, set relation, true
if: { field: columns, equals: 3 }
if: { field: reverse, not: true }
```

A node whose condition fails renders nothing: no wrapper, no placeholder. Exactly one of `equals` or `not`.

## 7. Globals

Header and footer use the section shape with `kind: global` and a fixed `name`:

```yaml
kind: global
name: header
fields:
  logo:
    type: image
    required: true
  navItems:
    type: array
    max: 6
    rowLabel: link
    fields:
      link: link
  cta: link
layout:
  - div: container flex items-center justify-between py-5
    as: header
    children:
      - button: { href: { value: / } }
        class: block
        children:
          - image: logo
            class: h-8 w-auto
      - each: navItems
        as: nav
        class: hidden items-center gap-7 md:flex
        children:
          - button: link
            variant: button.link
      - button: cta
        variant: button.primary
        if: cta
```

A global compiles to a Payload global whose slug stays `header` or `footer`. There is no page slot: the frontend layout renders the header global, then the page, then the footer global ([payload-integration.md section 3](payload-integration.md#3-changes-by-file)).

## 8. Seeds

Seeds are optional and are only read by the seeder, never by the compiler.

```yaml
# seed/forms.yaml
- key: contact
  title: Contact
  submitButtonLabel: Send
  confirmationType: message
  confirmationMessage: Thanks, we will be in touch.
  fields:
    - { blockType: text, name: name, label: Name, required: true, width: 50 }
    - { blockType: email, name: email, label: Email, required: true, width: 50 }
    - { blockType: textarea, name: message, label: Message, required: true }
```

```yaml
# seed/globals.yaml
header:
  logo: "@media/logo.svg"
  navItems:
    - link: { type: reference, reference: "@page/home", label: Home }
    - link: { type: reference, reference: "@page/contact", label: Contact }
  cta: { type: custom, url: "mailto:hello@example.com", label: Say hello }
footer: { ... }
```

```yaml
# seed/pages.yaml
- slug: home
  title: Home
  sections:
    - hero-split:
        heading: Work that reads well.
        description: A studio for editorial brands.
        primaryButton: { type: reference, reference: "@page/contact", label: Start a project }
        image: "@media/hero.jpg"
    - contact:
        heading: Say hello
        form: "@form/contact"
```

Reference tokens: `@media/<file>` uploads `seed/media/<file>` once and reuses it; `@page/<slug>` and `@form/<key>` resolve after those documents exist (pages are created in two passes so links between them resolve). `richText` values are written as Markdown strings and converted with the Lexical package's Markdown converter. Field values are validated against the section's fields before anything is written.

## 9. Validation rules

The compiler rejects a template when any of these fails. Every message names the file, the line and column, the path inside the document, and what was expected.

1. The manifest's `theme`, `globals.*` and `sections` paths exist. `name` equals the folder name.
2. Field names match `^[a-z][a-zA-Z0-9]*$`, are unique per level and are not reserved. A hyphenated name reports the camelCase fix.
3. Section names match the kebab pattern and are unique in the template. Globals are named `header` and `footer`, once each.
4. Every `select` has at least one option; every `array` has at least one field; `relation.to` is a known collection.
5. Every reference resolves to a field in scope whose type the primitive accepts (6.1). Unknown names suggest the closest declared name.
6. Dot paths only traverse `link`, `image`, `relation` and `list` rows, and only to known properties.
7. `variant` references exist in the theme.
8. `as` is in the allowed list for that primitive. `div`, `each` and `list` have `children`; `button` may; no other node does. A literal button without `children` has a `label`.
9. `if` names a field in scope; `equals`/`not` values match the field's type.
10. `list.collection` is allowed, `limit` is 1 to 50, `sort` names a field of that collection, `where` placeholders name section fields.
11. Theme: `fonts.sans` set; colour tokens are from the slot list; `light` has the four required tokens; `radius` is a CSS length.
12. Arrays nest at most one level.

Warnings, which `--strict` turns into errors: a declared field never referenced in `layout`; a variant never referenced by any file; an `each` without `as` whose children are not `li` nodes inside a `ul`/`ol` (an accessibility hint, not a rule).
